## 2. Статус подсистемы аутентификации и авторизации

> [!WARNING]
> **Авторизация и аутентификация в проекте в настоящий момент НЕ реализованы.**
> Все эндпоинты API (`/students`, `/courses`, `/applications`) являются публичными и доступны без передачи токенов доступа.

### Рекомендации по реализации системы разграничения доступа:
1. **Внедрение аутентификации на основе JWT / OAuth2:**
   - Добавить эндпоинт `/auth/login` с проверкой хэшированного пароля (через `passlib` / `bcrypt`).
   - Использовать `OAuth2PasswordBearer` из FastAPI для извлечения `Bearer <token>` в заголовке `Authorization`.
2. **Ролевая модель доступа (RBAC):**
   - **Роль `Dean` (Замдекана / Сотрудник деканата):** полный доступ (CRUD студентов, курсов, просмотр всех заявок, запуск процедуры распределения).
   - **Роль `Student` (Студент):** чтение каталога курсов, создание/редактирование заявок *только от своего имени* (проверка `student_id == current_user.id`), запрет на модификацию курсов и чужих заявок.
3. **Ограничение частоты запросов (Rate Limiting):**
   - Интегрировать библиотеку `slowapi` для защиты от перебора идентификаторов и DoS-атак.
4. **Контроль CORS и заголовков безопасности:**
   - Настроить `CORSMiddleware` с явным перечислением доверенных доменов фронтенда (исключить `allow_origins=["*"]` в production-окружении).
   - Внедрить заголовки `Content-Security-Policy`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`.

## 3. Защита от SQL-инъекций и утечек информации

1. **Параметр поиска `search` в GET /courses:**
   - Поиск реализован через `col(Course.title).ilike(f"%{search}%")`.
   - Значение параметра передаётся движком SQLAlchemy в подготовленный запрос в качестве связанной переменной (bind parameter), что исключает внедрение управляющих SQL-конструкций (протестировано нагрузочными SQLi-пейлоадами в наборе тестов).
2. **Предотвращение утечки трассировок стека:**
   - Ошибки клиентского ввода обрабатываются через стандартные исключения `HTTPException` и валидаторы FastAPI / Pydantic.
   - Клиент получает стандартизированный JSON `{"detail": "..."}` без раскрытия путей на сервере, номеров строк кода и стека вызовов.
3. **Безопасность логирования:**
   - Логирование SQL-запросов в консоль (`echo=True` в `database.py`) выводит лишь структуру запросов и метаданные сущностей. Пароли и токены пользователей в системе не хранятся и в логи не попадают.
